# 掼蛋 AI 训练营 · 架构文档（ARCHITECTURE.md）

> 本文档是项目的"架构 Prompt"，任何会话在继续开发前必须先读本文件（配合根目录 [PROGRESS.md](../PROGRESS.md) 的最新进度），遵守已锁定的架构。

## 1. 项目背景
做一个网页版掼蛋新手训练营：真实完整的掼蛋对局流程（两副牌 · 4 人两两组队 · 从 2 打到 A 的升级制）+ 每次轮到玩家出牌时 AI 教练给出出牌方案和理由，帮助零基础玩家从第一局开始学会掼蛋。
本项目由原"斗地主 AI 训练营"全面改掼蛋而来：**逻辑层七个模块已完全重写并与斗地主脱钩**，表现层重构为 4 人对家对座牌桌。

## 2. 目标用户
完全不会掼蛋的新手玩家（需要教程、纠错提示、随时可看的 AI 辅导），也兼容有基础玩家与 BOT 练牌。

## 3. 核心需求（已实现）
1. 完整真实的掼蛋流程：两副牌 108 张（27×4 全发、无底牌）→ 级牌（打几）→ 轮流出牌/接风 → 头游定名次 → 升级判定 → 下一手打胜方新级牌 → 直到某方"过 A"赢下整场
2. AI 教练：轮到玩家时给出"建议出什么 + 为什么"，方案列表两段式点选（点一次选中、再点打出）；对玩家每次出牌给出点评
3. 出牌校验：选牌实时显示牌型与"是否压得上家"，非法牌型/压不过时用通俗中文解释原因（教学式纠错）
4. 不同难度的 BOT 对手：入门（随机型+犯错）/ 进阶（贪心型+偶尔忍牌）/ 高手（最少手数拆解、队友让牌、对手报牌压制）
5. AI 教练侧边栏：局势概览 + 中文分析 + 可点选方案列表（DD.buildPlans，推荐恒第一），桌面停靠 / 移动横屏抽屉+悬浮球
6. 学习辅助：内置新手教程（5 章节）、记牌器（含队友亮牌、可折叠、窄屏默认收起）、报牌红点、接风气泡、级牌推进图示、战绩累计（localStorage）
7. 事件与状态：出牌/过牌气泡、名次徽章、本手结算弹窗、整场过 A 弹窗+彩带

## 4. 架构设定
- 产品形态：Web 网页（单页应用：主页 / 对局 / 教程弹层）；桌面、窄屏抽屉、横屏手机紧凑档、超矮视口降级、竖屏旋转提示五档布局
- 架构模式：分层模块化（逻辑层 → 状态机层 → 表现层），无框架；表现层引用 :root 设计令牌（色彩/字号/间距/圆角/阴影/卡牌尺寸）
- 运行环境：纯本地，双击 index.html 即可运行（file:// 协议兼容，不用 ES Module）

## 5. 技术约束
- 语言：原生 HTML5 + CSS3 + JavaScript（ES2017+，无 TypeScript、无框架、无构建工具、零依赖）
- 模块组织：多 `<script>` 顺序加载（顺序见 index.html 底部），全部挂载到全局命名空间 `DD`（window.DD）
- 存储：localStorage（键 `dd_trainer_settings`、`dd_trainer_stats`）
- AI：全部客户端启发式算法（牌型识别 → 合法走法枚举 → 手牌拆解最少手数 → 策略决策），不调用任何外部 API
- 兼容目标：Chrome / Edge / Safari 现代版本

## 6. 非功能需求
- 逻辑层（rules/cards/combos/movegen/ai/advisor/game）不得接触 DOM，保证可在 Node 中做仿真测试（`node test/sim.js`）
- BOT 对局必须保证收敛（先手必有牌可出 → 对局必然结束）
- 布局各档互不遮挡：用 `?debug=1` 包围盒 dump + 截图在三档分辨率（1400×900 / 956×440 / 844×390）验收
- 卡牌全部用 CSS 绘制，不依赖任何图片资源；音效由 WebAudio 代码实时合成（js/sfx.js），无音频文件、可开关

## 8. 关键设计决策（勿回退）
- **座位编号**：0=你（人类）, 1=下家（右）, 2=对家队友（亮牌）, 3=上家（左）；队伍 = idx % 2
- **级牌有效大小**：`DD.effOf` —— 2 最小…A(14)，级牌插到 A 之上(17)，小王 18、大王 19；同花顺同顶按 ♠>♥>♣>♦
- **万能配**：红桃级牌（每副 1 张，共 2 张）；analyze 时作为补位参与牌型，不能单独当王，总配数 ≤2
- **收轮判定**：一圈"其余未出完者全部过"即收轮，领出者（或接风者）直接再领出——**不要**要求领出者自过（旧实现曾因此导致人类玩家死局，test 已有回归断言）
- **接风**：trickLead 事件携带 `windfall` 标记（胜者已出完 = 接风）；接风对象也已出完时顺延到下一位未出完者
- **进贡**：`DD.RULES.gong` 预留开关（默认 false）；实现时需联动 dealHand 的首手决定与 UI，引擎注释已标记位置
- **升级表**：双上（头游+队友二游）+3 / 头游+三游 +2 / 头游+末游 +1；过 A 要求本方头游且队友非末游

## 9. 验收标准
- 打开 index.html 能完成 发牌→出牌→接风→本手结算→下一手→过 A→整场结算 全流程，无 JS 报错
- AI 教练在每次玩家回合给出具体方案与理由；非法出牌有通俗解释
- 三档难度 BOT 行为有可感知差异；`node test/sim.js` 全绿（39 断言 + 60 手仿真 + 整场）
- 布局三档分辨率 `?debug=1` 几何无交叠；横屏手机与竖屏提示正常
- 交互：两段式方案、展开分析才金框、双击单张直出、空格/P/Esc 快捷键、记牌器折叠、各开关、教程五 tab

## 10. 限制条件（不要做什么）
- 不引入 npm/构建工具/CDN 依赖，不使用 ES Module（保证 file:// 直接打开）
- 不做联网对战、不做后端、不接外部大模型 API（教练为内置启发式 AI）
- 不引入图片/音频素材文件（音效仅允许 WebAudio 代码合成）
- 不过度设计：不做房间系统/皮肤/在线排行等超出核心需求的功能
